### Phase 17 — UI 打磨与加载时序修复（v1.0.1）✅

实测驱动修复 5 项体验问题（用户截图反馈 + CDP/像素级自动化验证）：

- [x] **人物站位对齐**：basePos 从硬编码 `(2.2, -0.15)` 改为动态计算——水平精确对齐工具栏中心（随分辨率/DPI 自适应），脚底落在工具栏顶部上方 24px；用 `Box3.setFromObject` 实测模型包围盒补偿 VRM 资产“原点不在脚底”的偏差（feetOffsetY，换任意模型自动适配）。像素验证：人物中心 vs 工具栏中心偏差 ~1px
- [x] **打招呼手势重做**：wave / return（欢迎动画）改为“手臂举至头侧同高、掌心朝向观众、轻摆”（参考用户示意图）；基于 VRM normalized 骨骼规范编写几何计算脚本（`.temp/gesture_calc.mjs`）推算手端位置与掌心法向，两轮收敛到目标姿势
- [x] **工具栏 hover 死区修复**：`MouseInteractionController._uiHover()`——鼠标位于工具栏矩形 ±20px 内保持 near（隐藏态也算，兼作唤出手段），聊天/设置/换装面板同步保护（面板打开时点击不再穿透）；`Toolbar` 淡出防抖 260ms。修复“鼠标从人物移向工具栏时工具栏消失/点不到按钮”
- [x] **首次启动延迟显示**：`BrowserWindow show:false` + `window:show` IPC（模型就绪 + 渲染循环启动后揭示）+ 15s 超时兑底；`AvatarController.setModel` 去掉加载完成瞬间的 `setOpacity(1)`。消除启动时“纹理未就绪的半成品人物”闪现
- [x] **唤醒/休息纹理保护**：定位到窗口隐藏期间 Chromium 回收 GPU 纹理（实测唤醒后 ~640ms 才恢复，期间渲染为无纹理虚影且 opacity 无法遮盖 MToon outline/shade pass）→ 唤醒时 canvas 先 `visibility:hidden` 700ms（元素级隐藏：合成跳过但 WebGL 绘制照常执行、纹理静默重传），再揭示并淡入；`main.js` 注册 `disable-renderer-backgrounding` / `disable-backgrounding-occluded-windows` / `disable-background-timer-throttling` 三开关从根源阻止隐藏窗口资源降级；`ActionDispatcher.run` 入口 token 失效机制防止等待期被后续动作顶掉
