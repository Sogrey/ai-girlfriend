一、产品概述

1.1 一句话定位

一个长期驻留在 Windows 桌面上的实时 3D AI 虚拟伴侣：透明无边框窗口中的 VRM 角色，能看着你的鼠标、听你说话、开口回应并同步口型、做动作、表达情绪、换装、离开休息与召回——像一个真正"住"在电脑里的人。

设计愿景：打开程序后，用户桌面上多了一个会说话、会看着自己、会做动作、会回应自己的 3D AI 角色。她不是网页弹窗，不是聊天工具，而是桌面本身的一部分。

1.2 目标用户

  • 长时间使用 Windows 工作站办公的独居青年 / 技术从业者
  • 需要 AI 陪伴但抗拒传统"聊天框"形态的用户
  • 桌面美化爱好者（Wallpaper Engine、桌面宠物用户群）

1.3 核心价值

真实存在感

透明窗口 + 全屏眼神追踪 + 物理 Idle（呼吸/眨眼/发丝物理），角色有"活着"的感觉

多模态自然交互

语音（说）→ STT → LLM → TTS（听）→ 口型同步（看），全链路延迟秒级

主动行为能力

LLM 输出结构化 JSON（emotion + action），角色执行换装/离开/返回等真实动作

可成长人格

System Prompt 独立文件 + 角色名/称呼/性格可配 + 上下文记忆

服务可插拔

LLM 双 Provider（DeepSeek/Ollama）+ TTS Provider 架构化，业务与服务解耦

五、技术架构

5.1 进程拓扑

  • Electron 主进程：窗口/托盘/快捷键/鼠标轮询/app:// 协议
  • Renderer（Chromium）：Three.js 场景 + VRM 驱动 + 动画/表情/口型/眼神/拖拽/语音 VAD + UI
  • Python Backend：WebSocket 8765 + DeepSeek/Ollama LLM + Faster-Whisper CUDA + Edge-TTS + 统一对话管道

5.2 通信协议（WS，JSON + base64）

方向消息类型载荷说明
R→Buser_message{text} 文字对话
R→Btranscribe_audio{data: base64 webm/opus} 语音识别
R→Bspeak_line{text, emotion} 本地台词直读（摸头反应）
R→Breload_config 等控制类：重载配置/ping/状态/清历史
B→Rstt_result{text} 识别结果
B→Rai_response{reply, emotion, action, costume} 结构化意图
B→Rtts_audio{seq, final, data: base64 mp3} 逐句音频
B→Rstatus / error状态广播与中文错误提示

5.3 Action 协议（LLM → 渲染）

{"reply": "...", "emotion": "happy|shy|angry|sad|surprised|caring|neutral",
 "action": "idle|wave|leave|return|change_costume|comfort|head_pat|jump|dance|think",
 "costume": "casual|school|stylish|gothic|seed|null"}

校验层（backend/actions/definitions.py）：非法值归一、动作别名映射（pat→head_pat）、change_costume 缺失时从回复文本猜服装关键词（水手服→school 等）。
